# Phase 27 - Stale Artifact Renewal and Deep Research Controller

Purpose:
Turn stale generated artifacts into better governed renewal blueprints instead of deleting them or pretending they are current.

Operating Model:
Phase 27 is internal-only. It preserves source truth, classifies stale generated derivatives, and creates deep-research and regeneration plans for future review.

It does not:

- delete artifacts
- fetch external data
- contact external parties
- submit proposals
- approve work
- use credentials
- bypass Phase 5 or Phase 6

## Renewal Doctrine

Stale generated artifacts are not active work authority.

They are historical derivatives that can be used as learning material only after truth, freshness, and source provenance are preserved.

## Deep Research Function

For each stale candidate, Phase 27 creates:

- research questions
- local evidence to inspect
- fresh context requests
- platform and legal review prompts
- customer value checks
- technical scope checks
- payment and contract checks
- audit packet requirements

External research is only a proposed operator-scheduled action. Phase 27 itself does not browse or fetch.

## Regeneration Function

For each stale candidate, Phase 27 produces a regeneration blueprint:

1. Preserve the Phase 2 source snapshot.
2. Treat Phase 4+ artifacts as generated derivatives.
3. Confirm whether the source is still valid.
4. Regenerate Phase 3 through Phase 5 only from fresh governed context.
5. Rerun quality, truth, freshness, capability, and renewal checks.
6. Keep external action blocked until scoped Phase 5 approval and Phase 6 scope match.

## Output

Phase 27 outputs only internal `stale_artifact_renewal_record` artifacts.

It upgrades the stale-artifact problem into an auditable renewal queue.
